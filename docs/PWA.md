# Offline, installation, and updates

## Installation

The manifest (generated by vite-plugin-pwa) declares:

- `name` "ATMOS: Weather, without the noise", `short_name` "ATMOS"
- `display: standalone`, `orientation: portrait`, `scope: /`, `start_url: /`
- `theme_color` and `background_color` `#FAFAF8`
- Icons: 192px and 512px (`purpose: any`), 512px maskable, and a 180px apple-touch icon linked in `index.html`

Verified in this build:

- The manifest is served and parses (`/manifest.webmanifest`).
- All icon files exist and are PNG.
- The service worker (`/sw.js`) is generated and served.

Not verified:

- The browser's actual install flow. In a Chromium session the header Install button appears, which means `beforeinstallprompt` fired. Clicking it and completing installation was not tested.
- Android, iOS, and desktop-installed standalone behavior. iOS uses Add to Home Screen; the Settings page explains this.

The Install button renders only when the browser offers a prompt. It is hidden when ATMOS is already running standalone.

## Caching

| What | Strategy | Notes |
|---|---|---|
| App shell, JS, CSS, fonts, icons | Precache (Workbox) | 18 entries, about 480 KB, versioned by build |
| Forecast API | NetworkFirst, 6 s network timeout, 24 h max age, 20 entries | Used when the live request is slow or fails |
| Geocoding API | NetworkFirst, 6 s timeout, 7 day max age, 40 entries | Recent searches work offline |
| Navigation | Falls back to `index.html` | Deep links such as `/forecast/2026-10-16` resolve offline |

The app also keeps its own forecast snapshot in localStorage (`atmos.snapshots.v1`). This is the authoritative offline source for the UI. It is keyed by place, so it cannot be shown under a different city. Snapshots older than 7 days are not shown.

## Offline behavior

| Situation | What the user sees |
|---|---|
| Live request succeeds | "Live, updated HH:MM" in the place's timezone |
| Live request fails, snapshot exists | Snapshot values, "Cached forecast, last updated HH:MM. Not live.", and a note that the refresh failed |
| Offline, snapshot exists | Same as above |
| Offline or failed, no snapshot | Honest empty state ("You are offline." or "Could not reach the weather service.") with a retry action, and no invented values |
| Snapshot older than 7 days | Treated as absent |

The label is always shown on cached data. The "Live" label appears only when the forecast was received in the current session.

## Updates

Registration uses `registerType: 'prompt'`:

1. A new build is deployed. The new service worker installs and waits.
2. When it is ready, ATMOS shows a banner: "A new version of ATMOS is ready." with Update and Later.
3. Update activates the new worker and reloads. Later dismisses the banner. Nothing reloads without the user's choice, so unsaved state is not discarded.
4. Old precache entries are removed (`cleanupOutdatedCaches`).

Verified: a stale bundle is served from the service worker cache until the worker updates, which is expected for this flow. Not verified: the banner flow end to end, which needs two consecutive production builds.

## Storage limits

- Snapshots: at most 12 places, each the latest forecast only.
- Saved places: at most 6.
- localStorage writes that fail are caught. The app continues in memory and shows no fabricated values.

## Clearing data

Settings, then "Clear local data", then confirm. This removes saved places, preferences, and snapshots from this browser.
